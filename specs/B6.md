# B6 Segment loop

Source: ATLAS V1 Build Guide, Claude Code pack tab, section 4. Exported 24 November 2026 in session S00.

```text
Read CLAUDE.md and specs/framework.md (Stage 4 and Stage 5, including the reasoning check). This is step B6, the core of ATLAS. Plan first, and write the src/domain tests before any UI.
The video player follows specs/video-board.md.
Domain (pure TypeScript, unit tested):
- routing.ts: pickNextVersion(seenVersionIds, misconceptionCodes, pupilInterests, versions) returns the unseen version with the most matching misconception tags; ties go to the version with the most matching interest tags; returns null if none is unseen.
- tries.ts: given attempts for a segment, return the try number, whether the segment is complete, and whether to move on (after 3 failed tries).
Flow:
1. Choose the first version by interests. Play it from local storage.
2. Show the check item for this try. Typing is the default; a "Choose an answer" button shows tap options. Then the sure or not sure tap.
3. Ask "Why do you think so?" every time, right or wrong. Typing by default, with tap reason options available.
4. Call the ai-check Edge Function. Show the read-back: "Here's what I understood: ... Is that right?" If the pupil says no, let them edit once and re-check.
5. Correct answer and sound reasoning: mark the segment complete with a calm "Well reasoned" message.
6. Otherwise: use the try. Before try 2 and try 3, call pickNextVersion. If it returns null, show the worked-example card instead of a video.
7. After the third failed try: show "We'll come back to this one. You're not behind.", set segment_status to moved_on, create a stalled flag, and continue to the next segment.
8. If ai-check returns safeguarding = true: show a neutral "Thank you for sharing. A teacher may check in with you." and create a safeguarding flag. Do not show any verdict for that answer.
9. Record everything in attempts, including time taken and whether the answer was changed.
Done when: routing and tries tests pass; a tester can force every path in the framework diagram on a phone; every attempt row is complete.
```

- tries.ts counts tries per round; a round has 3 tries.
- Migration: attempts.round and segment_status.round (default 1), and a server function that starts a round for the signed-in pupil (D-29). Status never goes down.
- UI: a secondary "Relearn" button at the end of a segment, after "Well reasoned" and after "We'll come back to this one".
- Done when also: a tester can relearn a complete and a moved-on segment on a phone, and the moved-on one becomes complete and its flag clears when they get it.
