# B2 Accounts

Source: ATLAS V1 Build Guide, Claude Code pack tab, section 4. Exported 24 November 2026 in session S00.

```text
Read CLAUDE.md. This is step B2: accounts. Plan first.
Pupils have no email or phone. Design:
1. Admin creates a class and N pupils from the web admin. Each pupil gets a 6-character code (no ambiguous characters like 0, O, 1, I) and sets a 4-digit PIN on first sign-in.
2. Implement pupil sign-in as a Supabase Edge Function that checks code and PIN and returns a session for that pupil's auth user. Store only a hash of the PIN. Lock the code for 15 minutes after 5 wrong PINs.
3. Admin can print a sheet of pupil codes for a class.
4. After first sign-in, show the AI notice screen once (text from specs/B2-ai-notice.md, which Bright supplies). Record ai_notice_seen_at.
5. A pupil cannot start lessons unless consent_on is set by the admin.
Done when: 3 test pupils sign in on 2 phones, each sees only their own data, wrong PINs lock as described, and a pupil without consent sees a polite waiting screen.
```
